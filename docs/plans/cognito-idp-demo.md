## Что нужно сделать

1. Поднять в AWS IDP (identity provider) — «кубик, который прям определённо называется,
   и там нет вправо-влево», обязательно cloud-native.
2. Разобраться, какие в нём есть типы аутентификации, выбрать **самый популярный**.
3. Сделать минимальное приложение (веб или мобильное, любой стек — «на чём ближе»)
   и прикрутить к нему логин/пароль через этот IDP.
4. Ответить на организационный вопрос: **можно ли бесплатно?** Если нет — найти,
   какие есть подписки/тарифы в кабинете AWS.

## Решения

| Развилка | Выбор | Почему |
|---|---|---|
| Какой сервис = «IDP-кубик» | **Amazon Cognito User Pool** | Единственный cloud-native IDP в AWS для пользователей приложения. `IAM Identity Center` — это про доступ сотрудников к самому AWS, не подходит. Совпадает с «прям определённо называется, нет вправо-влево» |
| Тип аутентификации | **OIDC Authorization Code + PKCE** через страницу входа Cognito | Отраслевой стандарт для SPA и самый распространённый flow. Альтернативы в Cognito: SRP, `USER_PASSWORD_AUTH`, passwordless, федерация через Google/SAML — их достаточно перечислить в отчёте |
| Managed Login или классический Hosted UI | **Managed Login** (тариф Essentials), fallback — Hosted UI на Lite | Это две разные страницы, не синонимы: Managed Login доступен с тарифа **Essentials** и выше, классический Hosted UI — на всех тарифах, включая Lite ([docs](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-sign-in-feature-plans.html), 17.08.2026). На стоимость демо не влияет ни один из вариантов |
| Фронтенд | **React + Vite + `react-oidc-context`** | Минимум кода: провайдер + две кнопки. Cognito сам отдаёт готовый конфиг для этой связки |
| Как создавать ресурсы | **Консоль AWS** | Быстрее для первого раза и заодно закрывает требование «понять, что там есть несколько типов аутентификации» — это видно только глазами в UI |
| IaC | `[опционально]` Terraform поверх, после рабочего демо | Воспроизводимость и git-история в ветке — плюс к результату, но не в критериях приёмки |
| Хостинг | **localhost** (`http://localhost:5173`) | Cognito разрешает localhost как callback URL. Публичный S3+CloudFront — `[опционально]` |

## Ответ по деньгам (проверено 17.08.2026)

**Бесплатно.** Для демо на 1–5 пользователях выйдет **$0**:

| Что | Free tier | Дальше |
|---|---|---|
| Cognito **Lite** | 10 000 MAU/мес на аккаунт | $0,0055/MAU (первые 90 000) |
| Cognito **Essentials** (нужен для Managed Login) | 10 000 MAU/мес на аккаунт | $0,015/MAU |
| Cognito **Plus** (threat protection) | нет free tier | $0,020/MAU |
| Федерация SAML/OIDC (Google и пр.) | 50 MAU/мес, независимо от тарифа | $0,015/MAU |
| AWS Lambda | 1 000 000 запросов + 400 000 GB-с в месяц | по прайсу |

Источники: [Cognito pricing](https://aws.amazon.com/cognito/pricing/),
[Lambda pricing](https://aws.amazon.com/lambda/pricing/) — проверено 17.08.2026.

Два нюанса для отчёта:

- Managed Login требует минимум тариф **Essentials**, но у него тот же free tier 10 000 MAU —
  выбор тарифа на стоимость демо не влияет.
- Free tier Cognito и Lambda — **бессрочные**, не «первые 12 месяцев»: pricing-страница Cognito
  говорит прямо, что free tier «does not automatically expire at the end of your 12-month AWS Free
  Tier term», у Lambda 1 млн запросов/мес — из категории always free. Отдельно уточнять в Billing
  не требуется.

Организационный блокер: даже для free tier аккаунт AWS требует привязанную карту.

## Риски

| Риск | Что делать |
|---|---|
| `redirect_mismatch` при возврате из Cognito — самая частая ошибка | Callback URL в консоли должен совпадать с адресом Vite **посимвольно**, включая порт и отсутствие слэша на конце |
| Не приходит письмо с кодом подтверждения | Лимит дефолтного отправителя — **50 писем в сутки на весь AWS-аккаунт** (не на пул), сброс в 09:00 UTC, увеличению не подлежит ([квоты](https://docs.aws.amazon.com/cognito/latest/developerguide/quotas.html), 17.08.2026). Для демо хватит с запасом, но не гонять «Resend code» десятками; при упоре — переключить на SES |
| Письмо ушло в спам | Отправитель — `no-reply@verificationemail.com`, не твой домен. Сразу проверять папку «Спам», а не переотправлять код (см. лимит выше) |
| Опечатка в email при регистрации | Hard bounce кладёт адрес в AWS-managed suppression list, и **снять его нельзя**, пока пул на дефолтном отправителе — адрес мёртв бессрочно. Для демо регистрироваться на реальный ящик, вводить адрес внимательно |
| Новый AWS-аккаунт активируется не мгновенно | Регистрацию делать первым делом, не откладывать на момент, когда уже нужно создавать пул |
| Ресурсы созданы в разных регионах | Зафиксировать регион в шаге 1 и не переключать селектор в консоли |
| Кастомная форма логина вместо Managed Login не работает | Flow `USER_PASSWORD_AUTH` в app client по умолчанию выключен. Не нужен, если идём через Managed Login |
| Нет карты для регистрации аккаунта AWS | Организационный вопрос — эскалировать Андрею сразу, он сам спрашивал про этот аспект |
